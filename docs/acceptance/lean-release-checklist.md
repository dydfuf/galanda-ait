## 제품·운영 안전성

- 원본에서 추출된 장소 카드가 있으면 원문 근거를 바꾸지 않는다. 새 자료로 복사해 수정한다.
- mutation은 기존 멤버십·소유권·revision 검증을 유지한다. 마이그레이션이나 기존 데이터를 삭제하지 않는다.
- 서버 오류 로그는 고정 이벤트와 request ID만 남기며 예외 원문·인증 진단을 출력하지 않는다.
- `bash scripts/dev-isolated.sh`는 공식 PostgreSQL 이미지, loopback DB, tmpfs, 최소 권한 Worker, 별도 임시 설정을 사용한다. 기존 `.dev.vars`를 읽거나 덮어쓰지 않는다.
- `node scripts/check-release-env.mjs <staging|production> <explicit-env-file>` 및 [로컬 개발](../local-development.md), [운영 runbook](../staging-operations-runbook.md)의 명시적 설정 검사를 따른다. 배포 환경이 비어 있는 것은 로컬 제품 코드 실패와 구분한다.

## 시각 검수

현재 실행의 Chromium 390×900 / 1280×900 화면을 직접 캡처해 검토했다.
로그인, 홈/여행 빈 상태, 생성/동행자, 초대, 공유 실패, 자료함, 단일안 홈/확정 요약,
확정 일정, 비교를 확인했다. 기존 둥근 3D 에셋·브랜드를 유지했다.
주요 수정은 CTA 위계, 한글 줄바꿈, 데스크톱 초대의 빈 공간, primary 버튼 대비다.
실제 light CTA `rgb(27,100,218)`와 흰 텍스트는 **5.41:1**이다.
dark 일정 화면도 직접 확인했고 주요 화면의 가로 넘침은 없었다.
키보드 Tab 이동과 실제 focus ring을 별도로 확인했다.
이 수치는 해당 버튼의 대비 확인이며 전체 접근성 인증이 아니다.
원본 화면/로그 ZIP은 외부 업로드하지 않는다.

## 증거의 한계와 인계

- 실제 DB 검증은 합성 데이터와 로컬 Worker의 staging 이메일 인증을 사용했다.
- 비교/확정 케이스의 후보 준비는 실제 API, 이후 의견·확정·일정 수정/확인은 실제 UI로 수행했다. mock 성공 응답을 실제 DB 통과로 세지 않는다.
- 전체 gate: `pnpm check` (Node 24, pnpm 9.15.1) **173파일·1,925테스트**, lint/DB drift/types/Web·AIT 빌드 통과. remote exact-head CI는 PR에 기록한다.
- 운영 미검증: 실제 OAuth provider, staging/production 배포 설정·도메인·DB 권한, 설치형 PWA/Toss 실기기, 실제 모바일 키보드·safe area.
- 최소 출시 절차: draft PR 검토·승인 → 승인된 환경 값/DB 권한 확인 → 별도 승인 후 배포 → 실제 OAuth/실기기 핵심 흐름 smoke test. 이 작업에서 merge/deploy하지 않는다.

검증 종료 시 임시 서버·DB·인증 설정을 정리하고 확인 결과를 PR에 기록한다.
