# 갈란다 그룹 여행 의사결정 제품 정의서

## 1. 문서 목적

이 문서는 친구들과 여행을 준비할 때 여러 여행안을 비교하고 하나의 공동 일정으로 확정하는 토스 미니앱 `갈란다`의 1차 제품 정의를 기록한다. 이후 화면 흐름, 정보 구조, 프로토타입, 개발 범위를 결정할 때 이 문서를 기준으로 삼는다.

현재 단계에서는 사용자가 합의한 제품 방향과 MVP 경계를 정의한다. 화면별 UI와 상세 운영 정책은 다음 단계에서 구체화한다.

## 2. 한 줄 정의

친구 3~8명이 날짜·도시·숙소·교통 조건을 포함한 여러 여행안을 비교하고 의견을 모아, 방장이 하나의 공동 일정으로 확정하는 토스 미니앱.

## 3. 문제 정의

친구들이 여행을 가기로 합의해도 목적지와 날짜는 바로 정해지지 않는다. 특히 해외여행은 같은 기간이라도 도시별 체류일, 숙소 가격과 객실 상황, 도시 간 교통편에 따라 가능한 일정이 달라진다.

현재는 이런 정보가 메신저의 링크, 캡처 이미지, 대화 속 의견으로 흩어진다. 그 결과 다음 문제가 반복된다.

- 어떤 안이 최신인지 알기 어렵다.
- 비슷한 여행안의 차이를 한눈에 비교하기 어렵다.
- 숙소 가격이나 만실 여부처럼 결정에 중요한 근거가 대화 속에서 사라진다.
- 각 구성원이 선호하는 안과 참여하기 어려운 안을 구분하기 어렵다.
- 의견을 모은 뒤에도 누가 어떤 안을 최종 확정할지 모호하다.

갈란다는 채팅을 대체하지 않는다. MVP에서는 여행안을 구조화해 비교하고, 의견을 모으고, 하나를 확정해 별도 일정으로 연결하는 구간을 우선 해결한다.

## 4. 목표 사용자와 사용 맥락

### 주 사용자: 여행 총무

- 친구 3~8명의 여행을 주도한다.
- 여행 자체는 가기로 합의했지만 국가, 도시, 날짜, 체류 배분은 정하지 못했다.
- 여러 사람의 의견과 예약 조건을 정리해야 한다.
- 구성원 의견과 현실적인 제약을 보고 최종안을 확정한다.

### 참여 사용자: 동행자

- 공유 링크로 여행방에 참여한다.
- 기존 여행안을 검토하고 선호나 어려움을 표시한다.
- 필요하면 기본안을 복제해 날짜나 도시별 체류일을 바꾼 대안을 제시한다.

### 핵심 사용 시점

여행을 가기로 합의한 직후부터 숙소·교통 예약을 확정하기 전까지가 핵심 사용 구간이다. 최종안이 확정된 뒤에는 선택된 안을 공동 일정으로 계속 확인한다.

## 5. 핵심 사용자 과업

> 친구들과 여행을 가기로 했지만 어디로 언제 갈지 정하지 못했을 때, 숙소와 교통 조건까지 포함한 현실적인 여행안을 함께 비교하고 싶다. 그래야 대화만 반복하지 않고 모두가 납득할 수 있는 일정을 확정할 수 있다.

대표적인 비교 상황은 같은 7~10일 여행이라도 `A안: 도쿄 7~8일·오사카 8~10일`과 `B안: 도쿄 7~9일·오사카 9~10일`처럼 도시별 체류 배분이 다른 경우다. 갈란다는 각 안의 숙소 가격·예약 가능 상태·교통 조건을 함께 보여줘 구성원들이 일정 차이의 실제 영향을 판단하게 한다.

## 6. 제품 원칙

1. **비교 단위는 여행지가 아니라 여행안이다.**  
   국가나 도시 이름만 투표하지 않고, 전체 날짜와 도시별 체류일을 하나의 안으로 묶는다.

2. **대안은 새로 쓰지 않고 복제해 만든다.**  
   기본안을 복제한 뒤 달라지는 부분만 수정해 안 사이의 차이를 명확히 한다.

3. **가격은 실시간 사실이 아니라 확인된 스냅샷이다.**  
   사용자가 링크, 가격, 예약 가능 상태, 확인 시각을 직접 기록한다.

4. **의견 표시는 자동 결정이 아니라 방장의 판단 자료다.**  
   구성원은 선호와 어려움을 표현하고, 방장이 최종안을 확정한다.

5. **참여 장벽은 낮추고 여행 정보는 보호한다.**  
   링크를 열면 최소한의 초대 맥락만 보여주고, 토스 로그인으로 참여한 뒤 전체 정보를 공개한다.

6. **계획과 일정은 독립된 기능으로 연결한다.**  
   여행안을 비교하는 `계획`과 확정된 내용을 사용하는 `일정`을 분리한다. 하나의 여행방 안에서 기능을 나누기 때문에 이후 여행 전·중·후 경험을 추가할 수 있다.

## 7. 핵심 제품 객체

### 여행방

하나의 그룹 여행 전체를 담는 상위 공간이다. 여행 제목, 방장, 참여자와 여행 상태를 가지며, 하위에 `계획`과 `일정` 기능을 둔다. 향후 여행 후 기능도 같은 여행방에 연결할 수 있다.

### 계획

여행안을 제안하고 비교하며 구성원 의견을 모으는 기능이다. 최종안이 확정된 뒤에도 검토했던 여행안과 의견 기록을 확인할 수 있다.

### 여행안

구성원들이 비교하고 의견을 표시하는 기본 단위다. 다음 정보를 포함한다.

- 안 이름과 제안자
- 전체 여행 날짜
- 국가와 도시 순서
- 도시별 도착일·출발일과 체류 박수
- 도시별 하나 이상의 체류 구간과 구간별 숙소
- 출국·도시 간 이동·귀국 구간과 구간별 대표 교통 정보
- 날짜별 핵심 장소
- 고정된 비용 기준 인원
- 구간별 그룹 총액과 자동 합산한 여행안 총액
- 비용 기준 인원으로 나눈 1인 예상 참고액
- 설명 또는 제안 이유

여행안의 비용 원본은 1인당 금액이 아니라 그룹 전체 금액이다. 비용 기준 인원은 여행안마다 고정하며, 여행방 참여자가 늘거나 줄어도 자동으로 바꾸지 않는다. 작성자가 기준 인원을 명시적으로 수정했을 때만 1인 예상 참고액을 다시 계산한다.

### 여행안 임시안

작성 중인 여행안은 작성자에게만 보이는 임시안으로 자동 저장한다. 다른 참여자의 계획 목록·비교·의견 대상에는 포함하지 않으며, 작성자가 명시적으로 제안한 뒤에만 공개 여행안이 된다.

공개 여행안을 수정할 때도 마지막 공개본은 그대로 유지하고 작성자 전용 수정본 하나만 둔다. 수정본을 반영하기 전에는 다른 참여자와 기존 의견에 영향을 주지 않는다.

### 예약 정보 스냅샷

여행안에 포함한 각 숙소·교통 구간에 사용자가 직접 기록하는 판단 근거다.

- 예약 링크
- 원화 기준 그룹 총액의 정확한 금액 또는 예상 범위
- 선택 입력한 현지 통화 원가
- 예약 가능, 확인 필요, 만실 상태
- 확인한 사람과 시각

가격과 예약 상태가 변할 수 있으므로 실시간 정보처럼 표현하지 않는다.

원화 예상액을 기본 입력으로 사용하고 현지 통화 원가는 필요할 때만 추가한다. MVP에서는 실시간 환율을 적용하지 않는다. 정확한 금액은 최솟값과 최댓값이 같은 범위로 취급하고, 여행안 총액은 각 구간의 최솟값과 최댓값을 각각 더해 계산한다. 가격 정보가 없는 항목은 합산에서 제외하고 누락 건수를 함께 표시한다.

같은 도시에서도 날짜가 이어지는 여러 숙소 구간을 둘 수 있다. 교통은 MVP에서 이동 구간별 대표 정보 하나만 기록하며, 실제 여정에 여러 교통편이 포함되면 세부 환승편을 나누지 않고 `환승 필요`로 요약한다.

### 구성원 의견

각 여행안에 `좋아요`, `괜찮아요`, `어려워요` 중 하나를 표시한다. `어려워요`를 선택하면 날짜, 가격, 이동 부담 등 짧은 이유를 함께 남긴다. MVP에서는 이름과 선택은 모든 참여자에게 공개하고, 구체적인 사유는 작성자와 방장만 확인한다.

### 확정 일정

방장이 선택한 여행안을 바탕으로 생성되는 별도 기능이다. 구성원 모두에게 날짜별 도시, 핵심 장소, 숙소와 교통 정보를 제공한다. 원본 여행안과 일정은 연결되지만, 계획 화면을 대체하지 않는다.

## 8. 핵심 사용자 흐름

1. 방장이 여행방을 만든다.
2. 전체 날짜, 도시별 체류일, 숙소·교통 후보가 포함된 기본 여행안을 작성한다.
3. 방장이 여행방 초대 링크를 공유한다.
4. 초대받은 사용자는 초대 맥락을 확인하고 `여행방 참여하기`를 누른다.
5. 사용자는 토스 로그인 후 여행방에 참여한다.
6. 참여자는 기본안을 검토하고 의견을 표시한다.
7. 다른 구성이 필요하면 기존 안을 복제해 날짜, 도시, 숙소 또는 교통을 수정한 대안을 제안한다.
8. 구성원들은 여러 안의 차이와 의견 현황을 비교한다.
9. 방장은 의견 현황과 어려운 이유를 확인해 하나의 여행안을 확정한다.
10. 확정된 여행안을 바탕으로 별도의 공동 일정이 생성된다.
11. 구성원은 `계획`에서 검토 기록을 보고, `일정`에서 확정된 여행 정보를 사용한다.

## 9. 권한과 의사결정 규칙

- 방장만 여행안을 최종 확정할 수 있다.
- 모든 참여자는 여행안을 열람하고 의견을 표시할 수 있다.
- 참여자는 기존 여행안을 복제해 새 대안을 만들 수 있다.
- 다른 사람이 만든 여행안을 직접 덮어쓰지 않는다.
- 여행안 작성자는 자신이 만든 안을 수정할 수 있다.
- 작성 중인 임시안과 공개 여행안의 수정본은 작성자만 볼 수 있다.
- 공개 여행안 수정 중에는 마지막 공개본을 다른 참여자에게 계속 보여준다.
- 일정·도시·숙소·교통·비용·기준 인원 변경을 공개본에 반영하면 기존 의견을 초기화한다. 이름과 설명만 바꾼 경우에는 의견을 유지한다.
- 확정 전에는 여러 여행안을 유지하고 비교할 수 있다.
- 모든 참여자는 한 번에 두 여행안의 차이를 비교할 수 있다.
- 방장은 의견과 예약 정보가 불완전해도 하나의 공개 여행안을 확정할 수 있다. 앱은 확정 전 미응답 의견과 예약 위험을 숨기지 않고 보여준다.
- 여행안을 확정하면 당시 여행안과 의견을 계획 기록으로 잠그고, 불완전한 상태를 포함해 별도의 확정 일정을 생성한다.

확정 후에는 계획을 다시 열지 않고 별도의 일정 기능에서 변경한다. 일정의 수정 권한과 변경 알림은 `IT-01` 구체화 단계에서 결정한다.

## 10. MVP 범위

### 포함

- 여행방 생성과 목록 확인
- 토스 공유 링크를 통한 초대
- 초대 화면과 토스 로그인 기반 참여
- 기본 여행안 작성
- 여행안 복제와 수정
- 작성자 전용 임시안 자동 저장과 명시적 공개
- 날짜와 도시별 체류일 구성
- 숙소 체류 구간·교통 이동 구간 및 예약 정보 스냅샷 수동 등록
- 그룹 총액의 정확한 금액·예상 범위 입력과 여행안 총액 자동 합산
- 여행안별 `좋아요 / 괜찮아요 / 어려워요` 의견 표시
- 여행안 간 핵심 차이 비교
- 방장의 최종안 확정
- 계획과 분리된 확정 일정 조회

### 포함하지 않음

- 숙소·항공·교통편 실시간 검색 및 재고 연동
- 실시간 환율 환산
- 앱 내 예약과 결제
- AI 여행안 자동 생성
- 비용 정산과 공동 가계부
- 시간대별 세밀한 일정표
- 별도의 그룹 채팅
- 자동 다수결 또는 만장일치 확정
- 투표 마감과 모든 참여자의 응답 의무화
- 여행방별 의견 사유 공개 범위 설정

후기, 정산, 사진 모아보기, 셀레브레이션 카드, 애니버서리 기념은 향후 여행 후 기능의 후보로 기록한다. 이를 수용할 수 있도록 여행방을 상위 공간으로 두지만, 해당 기능들은 MVP 범위와 출시 약속에 포함하지 않는다.

의견 사유 공개 범위는 향후 여행방을 만들 때 `전체 공개` 또는 `작성자와 방장만 공개` 중 선택하는 확장 후보로 둔다.

## 11. 앱인토스 활용 방향

### 공유 링크

여행방별 딥링크를 생성해 초대받은 사용자가 해당 초대 화면으로 바로 이동하게 한다. 앱인토스의 `getTossShareLink`가 지정 경로로 진입하는 공유 링크를 지원한다.

### 토스 로그인

별도 회원가입 폼을 만들지 않는다. 초대 화면에는 초대한 사람과 여행 제목 등 최소 정보만 표시하고, `여행방 참여하기`를 누르면 토스 로그인과 동의를 거쳐 전체 여행 정보를 공개한다.

### 메시지 알림

새 여행안 등록, 의견 요청, 최종 확정처럼 재방문 가치가 명확한 이벤트만 후보로 둔다. 앱인토스 메시지는 사용자 권한과 사전 문구 검수가 필요하므로 구체적인 발송 이벤트는 운영 정책 단계에서 확정한다.

### 내비게이션

- 화면 상단에는 앱인토스 전용 내비게이션 바와 TDS `TopNavigation` 패턴을 사용한다.
- 여행방 안의 `계획`과 `일정`은 TDS `Tab`으로 전환한다.
- MVP에서는 별도의 하단 탭바를 만들지 않는다. 앱인토스 공식 가이드에 따라 하단 탭바가 꼭 필요한 전역 기능이 생겼을 때만 토스의 플로팅 형태를 검토한다.
- 향후 여행 후 기능이 추가되면 같은 여행방의 콘텐츠 구조 안에서 내비게이션을 다시 확장한다.

### 플랫폼 제약

- 미니앱 내 로그인은 토스 로그인을 사용한다.
- 현재 앱인토스 이용 대상은 만 19세 이상이다.
- 예약 링크의 외부 이동 방식과 심사 적합성은 화면 설계 전에 확인한다.

## 12. 제품 성공 정의

### 핵심 성공 행동

방장이 여행방을 공유하고, 참여자들이 여행안에 의견을 남기거나 대안을 제안한 뒤, 하나의 여행안을 확정하는 것.

### 초기 확인 지표

- 여행방 생성 후 기본 여행안 작성 완료율
- 초대 링크를 받은 사용자의 여행방 참여율
- 참여자 중 한 개 이상의 여행안에 의견을 남긴 비율
- 여행방당 제안된 대안 수
- 여행방 생성 후 최종안 확정률과 확정까지 걸린 시간

목표 수치는 실제 사용 데이터를 확보한 뒤 설정한다.

### 보호 지표

- 로그인 또는 초대 진입 실패율
- 첫 참여자 의견 없이 이탈한 여행방 비율
- 확인 시각이 없는 가격 스냅샷 비율
- `어려워요` 사유가 확인되지 않은 채 확정된 비율

## 13. MVP 완료 조건

- 방장이 여행방과 기본 여행안을 만들 수 있다.
- 초대받은 사용자가 링크를 통해 초대 화면에 도달하고 토스 로그인 후 참여할 수 있다.
- 참여자가 여행안의 날짜, 도시별 체류일, 숙소·교통 근거를 이해할 수 있다.
- 참여자가 여행안을 복제해 다른 체류 배분을 제안할 수 있다.
- 구성원별 의견과 `어려워요` 사유가 방장에게 보인다.
- 방장이 하나의 안을 확정하면 모든 참여자가 별도의 `일정` 기능에서 같은 공동 일정을 볼 수 있다.
- 가격과 예약 가능 상태에는 확인한 사람과 시각이 표시된다.

## 14. 열린 질문

화면 흐름 구체화 단계에서 다음을 결정한다.

- 확정 일정에서 누가 무엇을 수정하고 변경 내용을 어떻게 알릴지
- 오래된 가격과 예약 상태를 언제, 어떻게 다시 확인하도록 유도할지
- 외부 예약 링크를 여는 경험과 앱인토스 심사 요건
